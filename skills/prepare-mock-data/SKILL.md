# Mock 数据准备

读 `01-change-analysis.md` 的外部接口依赖和 `02-scenarios.md`，产出 `03-mock-plan.md`。
产物结构见 [TEMPLATE.md](TEMPLATE.md)，红线见 `../generate-api-tests/CONVENTIONS.md`。

## 批次范围

只处理**当前批次**的场景。先读 `02-scenarios.md` 的「批次」列，筛出本批次场景，
其余场景一律不碰——它们的 mock 等轮到那一批再设计，提前做会因为前置变化白费。

产物落到 `docs/batch<N>/03-mock-plan.md`，状态头的阶段写成 `batch<N>/03-mock 方案`。

## 关于 mock 平台

本 skill 只讲**通用方法论**：mock 方案的产物结构、决策矩阵、报文来源优先级、
与场景断言的对齐检查。**具体 mock 平台的接入方式**（怎么触发 mock 生效、怎么在平台上
配置报文、怎么把 CaseId 回填）由 vendor 适配 skill 提供。

如果本次运行的 vendor 提供了对应适配 skill（`prepare-mock-data-<vendor>`），
主编排会先调本 skill 讲方法论，再调适配 skill 讲平台细节。

如果没有可用的 mock 平台，本阶段允许跳过，在 `03-mock-plan.md` 里注明
"本环境不使用 mock" 并说明原因。

## 流程

### 1. 建决策矩阵

把「场景 × 依赖接口」摊成一张表，每格填两件事：该场景下这个接口会不会被调到、
需要它返回什么样的数据这个场景才成立。

### 2. 逐个接口与用户确认是否走 mock

**不要闷头全 mock。** 对每个接口给一句结论 + 一个具体理由，让用户拍板。

理由要能落到具体事实上，不能停在"构造成本高""逻辑复杂"这种半截话。可参照：

- **建议 mock**：`queryUserCoin` — FAT 库里都是有券用户，S2 要空返回，临时清号影响其他人在测的用例。
- **建议不 mock**：`queryCityInfo` — 228 城市 FAT 已有，接口就是按 id 查表，直连一次比配 mock 快。
- **建议 mock**：`queryPromotion` — 需要构造抛超时异常，真实环境没法稳定复现。

判断维度：真实环境能不能造出这个返回、造的代价、接口本身逻辑复杂不复杂、
其他并行测试会不会被这个 mock 影响到。

### 3. 生成 mock 报文

报文结构的来源按优先级：

1. 从代码里的 response DTO 类推导（字段名、类型、嵌套结构）；
2. 推导不出的字段，用 APM / trace 工具捞该接口的真实报文补全（具体工具见 vendor 适配）；
3. 仍不确定的，**明确指出是哪个字段**，问用户。不要用空值或猜测值糊过去。

每个场景一份完整 JSON，直接写在 md 的代码块里。

### 4. 报文与场景断言的一致性检查

生成报文后，把关键字段列一张表和 `02-scenarios.md` 的场景断言对比：

| 场景 | mock 里的关键值 | 场景断言里的期望值 | 一致？ |
|---|---|---|---|

不一致的必须在本阶段解决，不能带到阶段 5。

### 5. 聚合成方案并等待回填

- 一个场景聚成一组 mock 配置，含该场景下所有需要 mock 的接口。
- 报文完全一致的场景可以合并复用。
- md 末尾生成回填表，等用户去平台配置后填回对应 ID（列名由 vendor 适配定，默认 `MockId`）。
- 用户回填后校验完整性：漏填的场景标成"本次不使用 mock"并提醒用户确认。

### 6. 交接遗留数据需求

确认**不走 mock** 的接口，在 md 末尾的「遗留数据需求」章节写明：
要让接口 X 在场景 S 返回 Y，需要在真实环境准备什么数据。

这一节由 `prepare-framework-data` 直接消费，是保证依赖不漏的关键接缝，不能省略。
